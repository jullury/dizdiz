# AGENTS.md

## What this is

Linux-only tray app (`dizdiz`, PyQt6 + `evdev`) that plays a short sound on every
key press. Keystrokes are read **read-only** from `/dev/input/event*` and never
grabbed, buffered, or logged. Audio is played by spawning `pw-play` (PipeWire) or
`paplay` (PulseAudio); if neither is on `PATH` it runs silently. Python 3.11+.

Layout: `dizdiz/` (app modules), `dizdiz/assets/sounds/{pack}/*.wav` + `packs.json`
(manifest), `dizdiz/ui/` (Qt windows), `tests/`, `tools/`. Runtime state lives under
XDG dirs — always resolve paths through `dizdiz/paths.py`.

## Commands

- Run uninstalled: `python -m dizdiz` (or `pip install .` → `dizdiz` command)
- Tests: `pytest` (config in `pyproject.toml`: `testpaths=["tests"]`, `pythonpath=["."]`)
- Enable the commit-message guard (once per clone): `git config core.hooksPath .githooks`
- One test: `pytest tests/test_settings.py::test_defaults`
- Regenerate generated sounds: `python tools/make_sounds.py [laser|scifi|mechanical]`

## Verification reality

There is **no** linter, formatter, or type checker here. `pytest` is the only local
automated check and must pass. The only CI is `.github/workflows/release.yml`, and it
does not run tests — on every push to `main` it validates commit subjects, then runs
`python-semantic-release` to bump `pyproject.toml`, regenerate `CHANGELOG.md`, tag
`vX.Y.Z`, and create a GitHub Release. Commit subjects must be Conventional Commits
(hook: `git config core.hooksPath .githooks`); non-conforming messages fail both the
hook and the workflow.

## Architecture notes agents get wrong

- **The design docs describe a different architecture than the code ships.**
  `docs/superpowers/specs/2026-10-17-shotgun-keyboard-design.md` (tracked) and
  `.specify/memory/constitution.md` (gitignored, local-only) describe a single GLib
  main loop, `miniaudio` voice pool, GTK/Ayatana tray, a `src/shotgun_keyboard/`
  package, a control socket, and CLI flags (`--dry-run`, `toggle`, `status`). **None
  of that exists.** Shipped reality: PyQt6 `QSystemTrayIcon`, `evdev` reader, and
  `subprocess` players. Trust code + tests over those docs.
- `dizdiz/__main__.py` ignores argv — there are **no CLI flags**, despite the design doc.
- `KeyboardHook` (`dizdiz/keyboard_hook.py`) runs a background `threading.Thread` with a
  `select()` loop; the constitution's "single-threaded GLib, no application threads"
  principle does not reflect the code.
- Single-instance is an `flock` on `~/.config/dizdiz/dizdiz.lock` (`dizdiz/single_instance.py`),
  not `$XDG_RUNTIME_DIR`.

## Tests: conventions to preserve

- Isolation is done by monkeypatching **module-level functions**, e.g.
  `monkeypatch.setattr("dizdiz.settings.settings_path", ...)`,
  `dizdiz.autostart.autostart_entry_path`, plus `XDG_CONFIG_HOME`/`XDG_DATA_HOME`.
  Keep path lookups as lazy `dizdiz/paths.py` calls so they stay patchable.
- Qt tests use `pytest.importorskip("PyQt6")` + `QT_QPA_PLATFORM=offscreen`.
  `tests/test_settings_window.py` asserts that opening settings writes nothing to disk
  and does not change `sounds_enabled`; `SettingsWindow` relies on `blockSignals`
  during load and saves on each widget change.
- `tests/test_sound_catalog.py` enforces asset invariants: exact builtin pack id set,
  ≥3 sounds per pack, ≤0.8s duration, no extra RIFF chunks (no third-party metadata),
  and no byte-identical sounds within a pack.

## Changing sounds / packs

`dizdiz/assets/sounds/packs.json` is the manifest (sound ids are `pack.sound`, file
paths relative to `packs.json`). Renaming or removing a sound/pack means also updating
`LEGACY_PACK_IDS` / `LEGACY_SOUND_IDS` in `dizdiz/settings.py` so saved settings migrate
instead of silently falling back — tests assert migrated ids resolve.

Bundled sounds are first-party (generated by `tools/make_sounds.py`) except
`shotgun/reload.wav`; bundling any third-party audio requires provenance documented in
`tools/AUDIO_PROVENANCE.md`.
